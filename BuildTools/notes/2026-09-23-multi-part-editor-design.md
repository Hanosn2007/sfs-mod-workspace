# Part 页多选参数编辑：待确认的交互规则

## 当前可运行范围

目前 Part 页只在**恰好选中一个零件**时显示参数；多选时显示 `Select a part`。本轮先做单零件的可视化字段样例，不把下面的多选方案当作已经实现或用户已经同意的行为。

## 真实字段例子

本机蓝图中，`Fuel Tank` 保存数值字段 `fuel_percent`，`Engine Titan` 保存布尔字段 `engine_on`、`gimbal_on` 和 `heat_on__for_creative_use`。所查样本没有可直接编辑的 `thrust` 字段，因此不以“发动机推力”作为多选编辑例子。`PartSave.name`、字段类型和字段键共同决定一个字段是否可归为同一参数，不能只凭键名合并。

以选中 **2 个 Fuel Tank + 1 个 Engine Titan** 为例：

| 面板区域 | 显示 | 如果编辑，会影响谁 |
| --- | --- | --- |
| 全部零件共有 | 位置、朝向等所有被选零件都具有的属性；不同当前值显示“混合” | 3 个零件，位置变化应保留相对布局 |
| 部分零件适用（方案 A） | `Fuel (%) · 2/3`，明确指出只适用于燃料箱 | 只修改 2 个燃料箱；发动机仍保持选中，但它没有 `fuel_percent`，因此不新增此字段，也不改变发动机任何参数 |
| 另一部分零件适用（方案 A） | `Engine enabled · 1/3` | 只修改发动机；2 个燃料箱不受影响 |

方案 B 是只显示 3 个零件共同拥有的参数，将 `Fuel (%)` 和发动机开关都隐藏，直到选中同类零件。两种方案都能避免向不支持的零件写字段，但 A 更方便混合选区批量修改，B 更简单。**当前尚未确定使用哪一种**。

如果不同零件上出现同名字段，但类型或用途不同，应分行并标注适用零件类型，不按原始键名合并。多个适用零件的当前值不同时先显示“混合”；仅当用户明确输入或切换后才写入，不能在打开面板时把值统一。原始 JSON 仍只对应单个零件；多选面板不拼接或覆盖多份 JSON。

## 实施前还要验证

1. 用实际游戏对象核对多选集合变化事件、位置/朝向的坐标语义，以及撤销接口；一次批量应用应形成可撤销的一个操作。
2. 试两燃料箱一发动机的混合选择，确认“部分适用”是否采用方案 A，以及字段编辑后的选区、其他零件和撤销表现。
3. 再逐步为常见零件加入明确的字段标签；未知 Mod 零件保留原始字段，不猜字段含义或取值范围。
